\section*{Objetivo}
% ================================================================

El objetivo de este proyecto es implementar un \textbf{monitor de sistema} en lenguaje C enfocado en el
monitoreo del procesador y la memoria. La herramienta debe exponer al menos dos métricas dinámicas que se
actualicen en tiempo real, y puede presentarse como una aplicación de línea de comandos o con interfaz
gráfica básica.\\

Este reporte documenta el desarrollo incremental de dicha herramienta, organizado por \textbf{implementaciones},
cada implementación representa una etapa funcional completa que puede extenderse a lo largo de más de una sesión
de trabajo. El criterio que tomamos de avance no es el tiempo, sino la funcionalidad que se agrega en cada
implementación.\\

El plan de implementaciones es el siguiente:
\begin{enumerate}[leftmargin=1.5cm]
\item \textbf{Primer Implementación. Escaneo e impresión básica:} lectura de \texttt{/proc/meminfo} y
  \texttt{/proc/[pid]/} para obtener métricas de memoria y lista de procesos, salida por \texttt{printf}. Se
  establece también la infraestructura de compilación con CMake y el entorno reproducible con Docker.
  
\item \textbf{Segunda Implementación. Monitoreo de red (extensión futura):} incorporación de captura y análisis
  de paquetes de red al estilo de \texttt{iftop}, mostrando emisor, receptor, protocolo y volumen de tráfico.
  
\item \textbf{Tercer Implementación. Terminal interactiva con ncurses:} sustitución del \texttt{printf} por una
  interfaz de terminal estilizada que se actualiza en tiempo real. Se introducen dos hilos POSIX, uno recolector
  de datos y uno de dibujado, de modo que la interfaz nunca se congele independientemente de la carga del sistema.
\end{enumerate}

% ================================================================
\section*{Primer Implementación: Escaneo e impresión básica}
% ================================================================

El objetivo de esta primera implementación fue establecer la base del proyecto, definir las estructuras de datos
que representan el estado del sistema, leer las métricas de memoria y la lista de procesos activos desde el
sistema operativo, e imprimirlos en la terminal con \texttt{printf}. No hay interfaz especial, no hay
actualizaciones en tiempo real y no hay hilos. Se trata de un \textit{escaneo único}, el programa arranca, toma
una fotografía del sistema y termina.\\
La razón: antes de introducir complejidad concurrente (hilos, mutex) o de presentación (ncurses, GTK), es
necesario verificar que los datos que se leen son correctos. Con un \texttt{printf} simple nos permitimos
confirmar que las métricas tienen sentido antes de construir encima de ellas.

% ----------------------------------------------------------------
\subsection*{Arquitectura del código}
% ----------------------------------------------------------------

El proyecto se organiza en tres archivos fuente y un header:
\begin{itemize}[leftmargin=1.5cm]
\item \texttt{include/monitor.h}: definición de las estructuras de datos y declaración de las funciones públicas.
\item \texttt{src/monitor.c}: implementación de la recolección de datos y la impresión.
\item \texttt{src/main.c}: punto de entrada; orquesta las tres llamadas en secuencia.
\end{itemize}

% ----------------------------------------------------------------
\subsection*{Estructuras de datos: \texttt{monitor.h}}
% ----------------------------------------------------------------
La primera decisión de diseño fue centralizar todos los datos del sistema en dos estructuras:
\texttt{ProcessInfo} y \texttt{SystemSnapshot}.

\medskip

\texttt{ProcessInfo} representa un único proceso, sus campos mapean directamente con los archivos que el kernel
expone en \texttt{/proc/[pid]/}:

\begin{lstlisting}[style=modernc, caption={\texttt{monitor.h} struct ProcessInfo (líneas 12--21)}]
//Numero maximo de procesos que el snapshot puede almacenar
#define MAX_PROCS 512

/* Representa un unico proceso del sistema operativo,
   cada campo viene de una fuente distinta dentro de /proc/[pid]/ */
typedef struct
{
  int process_id;        //PID: identificador unico del proceso, fuente
  int parent_process_id; //PPID: PID del proceso que lo creo, fuente
  char name[256];        //Nombre corto del ejecutable, max 15 chars
  char cmdline[512];     //Comando completo con argumentos
  char parent_name[256]; //Nombre del proceso padre
  char state;            //Estado actual: R running, S sleeping, D waiting I/O, Z zombie, T stopped
  long vm_size_kb;       //Tamano total del espacio virtual en KB, incluye todo lo reservado aunque no esteen RAM
  long memory_kb;        //RSS en KB: paginas realmente en RAM ahora,  es la metrica de uso real de memoria
}
  ProcessInfo;
\end{lstlisting}

Cada campo tiene una fuente específica dentro de \texttt{/proc}:

\begin{itemize}
\item \texttt{process\_id} viene del nombre del directorio en \texttt{/proc};
\item \texttt{name} de \texttt{/proc/[pid]/comm}; \texttt{command\_line} de
\item \texttt{/proc/[pid]/cmdline}; \texttt{state}, \texttt{parent\_process\_id},
\item \texttt{memory\_kb} y \texttt{vm\_size\_kb} de \texttt{/proc/[pid]/status}.
\end{itemize}

\medskip

\texttt{SystemSnapshot} agrupa las métricas globales de memoria y el arreglo de procesos en una sola estructura
que se pasa por referencia entre funciones:

\begin{lstlisting}[style=modernc, caption={\texttt{monitor.h} struct SystemSnapshot (líneas 23--34)}]
/* Fotografia completa del estado del sistema en un instante
   agrupa metricas de memoria global y la lista de procesos */
typedef struct
{
  long memory_total_kb;   //RAM total instalada
  long memory_used_kb;    //RAM en uso real = total - free - buffers - cached
  long memory_free_kb;    //RAM completamente libre
  long memory_buffers_kb; //Cache de metadatos de filesystem
  long memory_cached_kb;  //Cache de contenido de archivos
  long swap_total_kb;     //Espacio de intercambio total
  long swap_used_kb;      //Swap en uso = SwapTotal - SwapFree
  ProcessInfo processes[MAX_PROCS]; //Arreglo estatico de procesos encontrados
  int process_count;                //Cuantas entradas validas hay en processes[]
}
  SystemSnapshot;
\end{lstlisting}

\bigskip

El arreglo \texttt{processes[MAX\_PROCS]} es estático con \texttt{MAX\_PROCS = 512}, de este modo evitamos
asignación dinámica de memoria (\texttt{malloc}) en esta primera etapa, simplificando el código a costa de un
límite fijo. En un sistema de escritorio típico el número de procesos rara vez supera los 400.

% ----------------------------------------------------------------
\subsection*{Restricción a Linux y portabilidad entre distribuciones}
% ----------------------------------------------------------------
La herramienta depende de \texttt{/proc}, un sistema de archivos virtual exclusivo del kernel Linux, lo que
significa que no compila ni corre en macOS, Windows ni BSD sin modificaciones.

\medskip

Sin embargo, \texttt{/proc} está presente en todas las distribucionesbasadas en Linux (Fedora, Ubuntu, Debian, Arch, Alpine) porque es una interfaz del kernel, no del sistema de paquetes, el mismo código que lee \texttt{/proc/meminfo} en Fedora funciona sin cambios en Ubuntu o Debian. El estándar que define su estructura está
documentado en \texttt{man 5 proc} y ha sido estable durante décadas.

\medskip

Para garantizar reproducibilidad entre máquinas con distintas distribuciones se introdujo un
\texttt{Dockerfile}, descrito al final de este documento.

% ----------------------------------------------------------------
\subsection*{Lectura de memoria \texttt{collect\_memory()}}
% ----------------------------------------------------------------
La función \texttt{collect\_memory()} lee el archivo \texttt{/proc/meminfo}, que el kernel regenera en cada
acceso con los valores actuales de memoria. Su formato es una lista de campos con el patrón \texttt{"Campo: valor kB"}:

\begin{lstlisting}[style=modernc, caption={\texttt{monitor.c} --- collect\_memory() (líneas 18--47)}]
/* Funcion para leer /proc/meminfo y extrae las metricas de memoria del sistema /proc/meminfo
   es generado por el kernel en cada lectura; cada linea tiene formato "Campo: valor kB" */
void
collect_memory(SystemSnapshot *system_snapshot)
{
  FILE *f = fopen("/proc/meminfo", "r");  //abrimos el archivo virtual del kernel
  if (!f)
    return; //Si no se puede abrir, salir sin modificar el snapshot

  char line[128]; //buffer para leer una linea a la vez
  long value; //variable temporal donde sscanf deposita el numero

  // Leemos linea por linea hasta EOF
  while (fgets(line, sizeof(line), f)) {
    /* sscanf intenta hacer match del patron en la linea
       Devuelve el numero de campos que pudo leer (0 o 1)
       solo guardamos el valor si el match fue exitoso (== 1) */
    if (sscanf(line, "MemTotal: %ld kB", &value) == 1)
      system_snapshot->memory_total_kb = value;
    else if (sscanf(line, "MemFree: %ld kB", &value) == 1)
      system_snapshot->memory_free_kb = value;
    else if (sscanf(line, "Buffers: %ld kB", &value) == 1)
      system_snapshot->memory_buffers_kb = value;
    else if (sscanf(line, "Cached: %ld kB", &value) == 1)
      system_snapshot->memory_cached_kb = value;
    else if (sscanf(line, "SwapTotal: %ld kB", &value) == 1)
      system_snapshot->swap_total_kb = value;
    else if (sscanf(line, "SwapFree: %ld kB", &value) == 1)
      system_snapshot->swap_used_kb = system_snapshot->swap_total_kb - value;
  }
  
  fclose(f); //siempre cerrar el archivo para liberar el descriptor

  /* Calculamos memoria realmente usada buffers y cached son reutilizables
     por el kernel cuando hay presion de memoria, por eso no se cuentan
     como "en uso real" por aplicaciones */
  system_snapshot->memory_used_kb = system_snapshot->memory_total_kb
                                    - system_snapshot->memory_free_kb
                                    - system_snapshot->memory_buffers_kb
                                    - system_snapshot->memory_cached_kb;
}
\end{lstlisting}

\bigskip

El archivo \texttt{/proc/meminfo} tiene un formato fijo garantizado por el kernel, la cadena \texttt{"MemTotal: \%ld kB"} es el patrón literal que aparece en el archivo, incluyendo los espacios y la unidad \texttt{kB}.
\texttt{sscanf} devuelve el número de campos que pudo leer exitosamente; al verificar \texttt{== 1} nos aseguramos de que el match fue completo antes de guardar el valor, si la línea no coincide con el patrón, \texttt{sscanf} devuelve 0 y simplemente pasamos a la siguiente. Se cumple de manera análoga para los demás casos.

\medskip

Linux usa la RAM libre para cachear contenido de archivos (\texttt{Cached}) y metadatos de filesystem
(\texttt{Buffers}), esta memoria aparece como ``usada'' pero el kernel la libera inmediatamente cuando una
aplicación la necesita. La fórmula correcta es:
\[
\texttt{used} = \texttt{total} - \texttt{free} - \texttt{buffers} - \texttt{cached}
\]
Esta es la misma fórmula que usan \texttt{htop} y \texttt{free -h}. Es por esta razón de qué \texttt{memory\_used} no es simplemente \texttt{total - free}.

% ----------------------------------------------------------------
\subsection*{Lectura de procesos \texttt{collect\_processes()}}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{monitor.c} collect\_processes() (líneas 49--122)}]
/* Funcion para iterar /proc buscando directorios numericos (cada uno es un PID)
   y extrae informacion de cada proceso vivo */
void
collect_processes(SystemSnapshot *system_snapshot)
{
  DIR *d = opendir("/proc"); //abrimos el directorio /proc como un iterador
  if (!d)
    return;

  struct dirent *entry; //entrada actual del directorio
  system_snapshot->process_count = 0;

   /* readdir devuelve la siguiente entrada cada vez que se llama,
      NULL cuando no quedan mas entradas */
  while ((entry = readdir(d)) != NULL && system_snapshot->process_count < MAX_PROCS) {
    
    /* Solo nos interesan entradas cuyo nombre empieza con digito
      /proc tiene directorios como "net", "sys", "self" que ignoramos */
    if (!isdigit(entry->d_name[0]))
      continue;

    int pid = atoi(entry->d_name);
    ProcessInfo p;
    memset(&p, 0, sizeof(p)); //inicializamos todos los campos a cero
    p.process_id = pid;

    char path[64];  //buffer para construir rutas como /proc/1234/comm
    char line[256]; //buffer para leer lineas de los archivos de status
    FILE *f;

    /* Contiene el comando completo con argumentos separados por '\0'
       ej: "/usr/bin/firefox\0--no-sandbox\0" 
       fread en lugar de fgets porque puede haber '\0' en medio */
    snprintf(path, sizeof(path), "/proc/%d/cmdline", pid);
    f = fopen(path, "r");
    if (f) {
      int len = fread(p.cmdline, 1, sizeof(p.cmdline) - 1, f);
      fclose(f);
      //Reemplazamos separadores '\0' por espacios para poder imprimirlo
      for (int i = 0; i < len - 1; i++)
	if (p.cmdline[i] == '\0') p.cmdline[i] = ' ';
      p.cmdline[len] = '\0';
    }

    /* Nombre corto del ejecutable, truncado a 15 chars por el kernel
       siempre disponible, incluso para hilos del kernel */
    snprintf(path, sizeof(path), "/proc/%d/comm", pid);
    f = fopen(path, "r");
    if (!f)
      continue; //si no podemos leer comm, el proceso ya termino saltar
    fgets(p.name, sizeof(p.name), f);
    p.name[strcspn(p.name, "\n")] = '\0';  //quitamos el newline final
    fclose(f);

    /* Archivo con multiples campos en formato "Campo:\tvalor"
       leemos State, PPid, VmRSS y VmSize de aqui */
    snprintf(path, sizeof(path), "/proc/%d/status", pid);
    f = fopen(path, "r");
    if (!f)
      continue;
    while (fgets(line, sizeof(line), f)) {
      long val;
      char c;
      int iv;
      if (sscanf(line, "State:\t%c", &c) == 1)
	p.state = c;
      else if (sscanf(line, "PPid:\t%d", &iv) == 1)
	p.parent_process_id = iv;
      else if (sscanf(line, "VmRSS:\t%ld kB", &val) == 1)
	p.memory_kb = val;
      else if (sscanf(line, "VmSize:\t%ld kB", &val) == 1)
	p.vm_size_kb = val;
    }
    fclose(f);

    /* Filtramos procesos del kernel: no tienen memoria de usuario (RSS = 0)
       hilos como kworker, migration, rcu_sched no aportan informacion util */
    if (p.memory_kb == 0)
      continue;

    //Leemos el comm del proceso padre usando su PPID
    if (p.parent_process_id > 0) {
      snprintf(path, sizeof(path), "/proc/%d/comm", p.parent_process_id);
      f = fopen(path, "r");
      if (f) {
	fgets(p.parent_name, sizeof(p.parent_name), f);
	p.parent_name[strcspn(p.parent_name, "\n")] = '\0';
	fclose(f);
      }
    }

    //Guardamos el proceso en el arreglo y avanzamos el contador
    system_snapshot->processes[system_snapshot->process_count] = p;
    system_snapshot->process_count++;
  }
  closedir(d); //Liberamos el descriptor del directorio
}
\end{lstlisting}

\bigskip

En Linux cada proceso vivo tiene un directorio en \texttt{/proc} cuyo nombre es su PID, por ejemplo \texttt{/proc/1234/}. No existe una llamada de sistema que devuelva directamente la lista de PIDs activos; la forma estándar
(la misma que usa \texttt{ps} y \texttt{top}) es iterar \texttt{/proc} y filtrar las entradas cuyo nombre sea
numérico con \texttt{isdigit()}.

\medskip

A diferencia de los demás archivos de \texttt{/proc}, \texttt{cmdline} no usa saltos de línea como separador
entre argumentos usa el carácter nulo \texttt{'\textbackslash0'}. Si usáramos \texttt{fgets}, la lectura se
detendría en el primer \texttt{'\textbackslash0'} y perderíamos todos los argumentos, \texttt{fread} lee los
bytes crudos y luego reemplazamos los \texttt{'\textbackslash0'} internos por espacios para poder imprimirlos.

\medskip

Los hilos internos del kernel (\texttt{kworker}, \texttt{migration}, \texttt{rcu\_sched}) aparecen como entradas
en \texttt{/proc} pero no tienen espacio de memoria de usuario asignado. Su \texttt{VmRSS} es 0, incluirlos no
aporta información útil para un monitor de memoria y solo ocupan entradas del arreglo.

\medskip

\texttt{VmRSS} (Resident Set Size) son las páginas del proceso que están físicamente en RAM en este momento.
\texttt{VmSize} es todo el espacio de direcciones virtuales reservado, que puede incluir regiones que el kernel
nunca ha cargado a RAM o que ya fueron movidas a swap. Para saber quién está \textit{realmente} usando memoria,
RSS es la métrica correcta.

% ----------------------------------------------------------------
\subsection*{Impresión y ordenamiento \texttt{print\_snapshot()}}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{monitor.c} print\_snapshot() (líneas 124--180)}]
/* Funcion para imprimir el snapshot completo, primero metricas de memoria,
   luego tabla de procesos ordenada de mayor a menor RSS */
void
print_snapshot(const SystemSnapshot *system_snapshot)
{
  /* --- seccion de memoria --- */
  printf("\n============== Memoria ==============\n");
  printf("  Total:   %10ld KB  (%ld MB)\n",
	 system_snapshot->memory_total_kb, system_snapshot->memory_total_kb / 1024);
  printf("  Usada:   %10ld KB  (%ld MB)\n",
	 system_snapshot->memory_used_kb, system_snapshot->memory_used_kb / 1024);
  printf("  Libre:   %10ld KB  (%ld MB)\n",
x	 system_snapshot->memory_free_kb, system_snapshot->memory_free_kb / 1024);
  printf("  Buffers: %10ld KB  (%ld MB)\n",
	 system_snapshot->memory_buffers_kb, system_snapshot->memory_buffers_kb / 1024);
  printf("  Cache:   %10ld KB  (%ld MB)\n",
	 system_snapshot->memory_cached_kb,  system_snapshot->memory_cached_kb / 1024);
  printf("  Swap:    %10ld KB usados / %ld KB total\n",
	 system_snapshot->swap_used_kb, system_snapshot->swap_total_kb);

  /* --- procesos ordenados por RSS --- */
  //Usamos memcpy para no modificar el arreglo original del snapshot;
  //qsort ordena en sitio usando cmp_mem como criterio
  ProcessInfo sorted[MAX_PROCS];
  memcpy(sorted, system_snapshot->processes, system_snapshot->process_count * sizeof(ProcessInfo));
  qsort(sorted, system_snapshot->process_count, sizeof(ProcessInfo), cmp_mem);

  printf("\n======================= Procesos con memoria (%d) =======================\n",
	 system_snapshot->process_count);
  printf("%-6s  %-6s  %-16s  %-10s  %-10s  %-8s  %-15s  %s\n",
	 "PID", "PPID", "Nombre", "RSS KB", "VmSize KB", "Estado", "Padre", "Comando");
  printf("%-6s  %-6s  %-16s  %-10s  %-10s  %-8s  %-15s  %s\n",
	 "------", "------", "---------------", "----------",
	 "----------", "-------", "---------------", "------------------------------");

  for (int i = 0; i < system_snapshot->process_count; i++) {
    const ProcessInfo *p = &sorted[i];

    //Truncamos cmdline a 40 chars, si esta vacio usar name como fallback
    char cmd_trunc[41];
    snprintf(cmd_trunc, sizeof(cmd_trunc), "%.40s",
	     p->cmdline[0] ? p->cmdline : p->name);
    
    printf("%-6d  %-6d  %-16s  %-10ld  %-10ld  %-8s  %-15s  %s\n",
	   p->process_id,
	   p->parent_process_id,
	   p->name,
	   p->memory_kb,
	   p->vm_size_kb,
	   state_str(p->state),
	   p->parent_name,
	   cmd_trunc);
  }

  //Resumen final
  if (system_snapshot->process_count > 0) {
    printf("\n  Mayor consumidor: %s  (PID %d)  %ld KB\n",
	   sorted[0].name, sorted[0].process_id, sorted[0].memory_kb);
    printf("  Menor consumidor: %s  (PID %d)  %ld KB\n",
	   sorted[system_snapshot->process_count-1].name,
	   sorted[system_snapshot->process_count-1].process_id,
	   sorted[system_snapshot->process_count-1].memory_kb);
  }
}
\end{lstlisting}

\bigskip

Antes de imprimir, la función copia el arreglo de procesos con \texttt{memcpy} y lo ordena con \texttt{qsort}
usando \texttt{cmp\_mem} como comparador, se ordena una \textit{copia} para no alterar el orden original del
snapshot, lo cual será importante cuando en implementaciones futuras otros hilos lean esos datos concurrentemente.

\medskip

El comparador \texttt{cmp\_mem} usa el idioma \texttt{(b > a) - (b < a)} en lugar de una resta directa
\texttt{b - a}. La razón es que \texttt{memory\_kb} es de tipo \texttt{long} y la resta podría producir
\textit{overflow} si los valores son muy grandes, corrompiendo el ordenamiento silenciosamente.

\subsection*{Punto de entrada: \texttt{main.c}}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{main.c} completo (líneas 1--17)}]
#include "monitor.h"
#include <string.h>

/* Punto de entrada del programa */
int
main()
{
  SystemSnapshot system_snapshot;
  /* Inicializamos toda la estructura a cero antes de usarla, sin esto los campos
     tendrian basura de memoria valores aleatorios que podrian hacer fallar los calculos */

  //Paso 2: iteramos /proc y llenar el arreglo de procesos

  //Paso 3: imprimimos todo lo recolectado

\end{lstlisting}

\texttt{main()} inicializa el snapshot con \texttt{memset} a cero antes de cualquier lectura, sin esto, los
campos del struct contendrían basura de la pila y los cálculos de memoria producirían valores incorrectos.
La secuencia es estrictamente lineal: recolectar memoria, recolectar procesos, imprimir.

% ----------------------------------------------------------------
\subsection*{Cómo funciona la red en Linux}
% ----------------------------------------------------------------

Antes de esta implementación, no tenía experiencia leyendo información de red desde el sistema operativo en C.
En la implementación anterior, la fuente de datos simplemente: \texttt{/proc/meminfo} y los directorios de PID.
Para la red, el primer desafío que se tuvo fue descubrir qué archivos leer y qué significan.

\medskip

Linux expone el estado de la red a través de \texttt{/proc/net/}, un subdirectorio del mismo sistema de archivos
virtual que ya conocíamos. Los archivos relevantes son:

\begin{itemize}[leftmargin=1.5cm]
\item \texttt{/proc/net/dev}: estadísticas acumuladas de bytes y paquetes por interfaz de red desde el arranque
  del sistema.
\item \texttt{/proc/net/tcp}: tabla de todas las conexiones TCP activas del sistema, con IPs y puertos en formato
  hexadecimal.
\item \texttt{/proc/net/udp}: ídem para UDP.
\item \texttt{/proc/net/nf\_conntrack}: tabla del módulo netfilter con bytes y paquetes por conexión individual.
  Solo accesible con privilegios de root y requiere que el módulo tenga la contabilidad habilitada.
\end{itemize}

\medskip

Lo que sí podemos leer \textbf{sin root}: \texttt{/proc/net/dev}, \texttt{/proc/net/tcp} y
\texttt{/proc/net/udp}. Con ellos obtenemos interfaces, bytes totales por interfaz y la lista de conexiones
activas con sus IPs. Lo que \textbf{requiere root}: \texttt{/proc/net/nf\_conntrack} para ver cuántos bytes
ha transferido cada conexión individual.

% ----------------------------------------------------------------
\subsection*{Estructuras de datos: \texttt{net\_monitor.h}}
% ----------------------------------------------------------------

Se definen tres estructuras que representan la red en un instante.

\subsubsection*{IfaceStats una interfaz de red}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.h}, struct IfaceStats}]
/* IfaceStats:
   estadisticas de una interfaz de red /proc/net/dev */
typedef struct {
  char name[32];   //nombre de la interfaz: eth0, wlan0, lo...
  long rx_bytes;   //bytes recibidos desde que arranco el SO
  long tx_bytes;   //bytes transmitidos desde que arranco el SO
  long rx_packets; //paquetes recibidos
  long tx_packets; //paquetes transmitidos
  int is_virtual;  //1 si es loopback, bridge o virtual
} IfaceStats;
\end{lstlisting}

Cada campo tiene una fuente directa en \texttt{/proc/net/dev}:

\begin{itemize}[leftmargin=1.5cm]
\item \texttt{name}: nombre de la interfaz, ej.\ \texttt{wlp1s0}, \texttt{lo}, \texttt{docker0}, es el
  identificador que el kernel asigna a cada dispositivo de red.
\item \texttt{rx\_bytes} / \texttt{tx\_bytes}: total de bytes recibidos y transmitidos desde que arrancó el
  sistema, son contadores acumulados, no la velocidad actual. Para calcular velocidad se necesitan dos lecturas
  separadas por un intervalo de tiempo.
\item \texttt{rx\_packets} / \texttt{tx\_packets}: número de paquetes procesados, un paquete es la unidad mínima
  de transmisión en red; su tamaño varía según el protocolo.
\item \texttt{is\_virtual}: campo que calculamos nosotros, no viene de \texttt{/proc}. Marca si la interfaz es
  virtual (no representa hardware real) para excluirla de los totales globales.
\end{itemize}

\medskip

\textbf{¿Qué es una interfaz virtual y por qué importa distinguirla?}
Una interfaz virtual es un dispositivo de red que existe solo en software, sin hardware físico detrás, los casos
más comunes son:
\begin{itemize}[leftmargin=1.5cm]
\item \texttt{lo} (loopback): permite que los procesos del mismo sistema se comuniquen entre sí por red sin salir
  al exterior. Todo lo que se envía a \texttt{127.0.0.1} pasa por aquí. Su tráfico no es tráfico real de
  internet.
\item \texttt{docker0}, \texttt{br-*} (bridges de Docker): Docker crea interfaces de tipo \textit{bridge} para
  conectar los contenedores entre sí y con el host. Si no hay contenedores corriendo, su tráfico es cero.
\item \texttt{veth*}: interfaces virtuales que Docker y otras herramientas de contenedores crean en pares para
  conectar un contenedor al bridge.
\item \texttt{virbr*}: bridges de \textit{libvirt} para máquinas virtuales con KVM/QEMU.
\end{itemize}

Las interfaces físicas (\texttt{wlp1s0}, \texttt{eth0}, \texttt{enp3s0}) son las que tienen hardware real
(tarjeta WiFi, Ethernet) y por las que fluye el tráfico real de internet. El campo \texttt{is\_virtual} nos
permite calcular totales que excluyan el ruido de las interfaces de software.

\subsubsection*{NetConn, una conexión activa}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.h} struct NetConn}]
/* NetConn:
   una conexion TCP o UDP activa asociada a un proceso
   /proc/net/tcp + /proc/[pid]/fd/ para cruzar con PID */
typedef struct {
  char protocol[8];      //"TCP" o "UDP"
  char local_addr[48];   //direccion local ip:puerto en texto
  char remote_addr[48];  //direccion remota ip:puerto en texto
  char remote_host[128]; //hostname resuelto de la IP remota
  char state[16];        //ESTABLISHED, LISTEN, TIME_WAIT, etc
  int pid;               //PID del proceso dueno del socket
  char proc_name[256];   //nombre del proceso
  long inode;            //inodo del socket, sirve para cruzar datos
  /* campos extra, solo disponibles con root via nf_conntrack */
  long bytes_sent;      //bytes enviados en esta conexion
  long bytes_recv;      //bytes recibidos en esta conexion
  long packets_sent;
  long packets_recv;
  int has_traffic_data; //1 si pudimos leer nf_conntrack
} NetConn;
\end{lstlisting}

\begin{itemize}[leftmargin=1.5cm]
\item \texttt{protocol}: \texttt{TCP} o \texttt{UDP} según el archivo de origen (\texttt{/proc/net/tcp} o
  \texttt{/proc/net/udp}).
\item \texttt{local\_addr} / \texttt{remote\_addr}: dirección IP y puerto en formato texto \texttt{"1.2.3.4:443"}
  , convertidos desde el hexadecimal que almacena el kernel.
\item \texttt{remote\_host}: resultado de la resolución DNS inversa de la IP remota. Si el servidor tiene un PTR
  record, aquí aparece su nombre de dominio en lugar de la IP numérica.
\item \texttt{state}: estado actual de la conexión según el protocolo TCP.
\item \texttt{pid}: identificador del proceso dueño del socket, se obtiene cruzando el campo \texttt{inode} con
  los file descriptors de cada proceso en \texttt{/proc/[pid]/fd/}.
\item \texttt{inode}: número de inodo del socket en el sistema de archivos virtual, es la clave para cruzar
  conexiones con procesos.
\item \texttt{bytes\_sent}, \texttt{bytes\_recv}, \texttt{packets\_sent}, \texttt{packets\_recv}: estadísticas de
  tráfico individuales por conexión. Solo disponibles cuando se corre como root y el módulo
  \texttt{nf\_conntrack} tiene la contabilidad habilitada.
\item \texttt{has\_traffic\_data}: bandera que indica si los campos de bytes contienen datos reales o están en
  cero por falta de permisos.
\end{itemize}

\subsubsection*{NetSnapshot, la fotografía completa}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.h} struct NetSnapshot}]
/* NetSnapshot:
   fotografia completa del estado de red en un instante */
typedef struct {
  IfaceStats ifaces[MAX_IFACES];
  int iface_count;
  NetConn conns[MAX_CONNS];
  int conn_count;
  //Totales globales sumados de todas las interfaces (excepto lo)
  long total_rx_bytes;
  long total_tx_bytes;
} NetSnapshot;
\end{lstlisting}

Al igual que \texttt{SystemSnapshot} en la implementación anterior, agrupa todos los datos de red en una sola
estructura que se pasa por referencia. Los campos \texttt{total\_rx\_bytes} y \texttt{total\_tx\_bytes} son la
suma de los bytes de todas las interfaces físicas (excluyendo virtuales), lo que da una visión global del
tráfico real del sistema.

% ----------------------------------------------------------------
\subsection*{Por qué se necesita sudo}
% ----------------------------------------------------------------

La mayor parte de la información de red es pública: cualquier usuario puede leer \texttt{/proc/net/tcp} y
\texttt{/proc/net/dev}. Sin embargo, hay dos cosas que requieren privilegios de root:

\begin{enumerate}[leftmargin=1.5cm]
\item \textbf{Leer \texttt{/proc/[pid]/fd/} de otros procesos.} Para cruzar los inodos de los sockets con PIDs,
  necesitamos abrir el directorio de file descriptors de cada proceso, el kernel restringe este acceso: un
  proceso solo puede ver los fd de procesos del mismo usuario. Como root, podemos ver los fd de todos los
  procesos y por eso el cruce PID $\to$ proceso es más completo.
  
\item \textbf{Leer \texttt{/proc/net/nf\_conntrack}.} Este archivo es propiedad del grupo \texttt{root} y no
  tiene permisos de lectura para otros usuarios. Contiene los contadores de bytes por conexión del módulo
  netfilter.
\end{enumerate}

La función \texttt{is\_root()} verifica esto con una sola llamada al sistema:

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} --- is\_root() (líneas 119--125)}]
/* Funcion que verifica si es root
   getuid() == 0 significa proceso corriendo como root */
int
is_root(void)
{
  return getuid() == 0;
}
\end{lstlisting}

\texttt{getuid()} es una llamada al sistema que devuelve el UID (User ID) real del proceso, en todos los
sistemas Unix/Linux, el UID 0 está reservado para root.

% ----------------------------------------------------------------
\subsection*{Funciones auxiliares internas}
% ----------------------------------------------------------------

Antes de las funciones públicas, \texttt{net\_monitor.c} define cuatro funciones privadas
(marcadas \texttt{static}) que se encargan de conversiones y utilidades.

\subsubsection*{hex\_to\_ip de hexadecimal a IP legible}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} --- hex\_to\_ip() (líneas 10--24)}]
static void
hex_to_ip(const char *hex, char *out, size_t out_size)
{
  unsigned int addr;
  sscanf(hex, "%X", &addr); //leemos el hex como entero sin signo
  struct in_addr in;
  in.s_addr = addr;         //asignamos sin reordenar bytes
  //inet_ntoa convierte struct in_addr a "A.B.C.D"
  snprintf(out, out_size, "%s", inet_ntoa(in));
}
\end{lstlisting}

El kernel almacena las IPs en \texttt{/proc/net/tcp} como enteros hexadecimales en formato \textit{little-endian}, por ejemplo, \texttt{0101A8C0} representa la IP \texttt{192.168.1.1}, la función lee el hex como entero sin
signo con \texttt{sscanf}, lo asigna directamente a \texttt{in\_addr.s\_addr} sin reordenar bytes (porque el
kernel ya lo almacena en el orden correcto para \texttt{inet\_ntoa}), y \texttt{inet\_ntoa} hace la conversión
final a texto.

\subsubsection*{hex\_to\_port de hexadecimal a puerto decimal}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} hex\_to\_port()}]
static int
hex_to_port(const char *hex)
{
  int port;
  sscanf(hex, "%X", &port);
  return port;
}
\end{lstlisting}

Los puertos también aparecen en hex en \texttt{/proc/net/tcp}. Por ejemplo, \texttt{01BB} es el puerto 443
(HTTPS). La conversión es directa con \texttt{sscanf \%X}.

\subsubsection*{tcp\_state\_str número de estado a texto}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} tcp\_state\_str()}]
static const char*
tcp_state_str(int st)
{
  switch (st) {
  case 1:
    return "ESTABLISHED";
  case 2:
    return "SYN_SENT";
  case 3:
    return "SYN_RECV";
  case 4:
    return "FIN_WAIT1";
  case 5:
    return "FIN_WAIT2";
  case 6:
    return "TIME_WAIT";
  case 7:
    return "CLOSE";
  case 8:
    return "CLOSE_WAIT";
  case 9:
    return "LAST_ACK";
  case 10:
    return "LISTEN";
  case 11:
    return "CLOSING";
  default:
    return "UNKNOWN";
  }
}
\end{lstlisting}

El kernel almacena el estado de cada conexión TCP como un entero en \texttt{/proc/net/tcp}, esta función mapea
ese entero a su nombre estándar según la especificación del protocolo TCP (RFC 793). Los estados más relevantes:

\begin{itemize}[leftmargin=1.5cm]
\item \textbf{ESTABLISHED}: conexión activa, ambos lados intercambian datos.
\item \textbf{LISTEN}: el proceso espera conexiones entrantes (un servidor).
\item \textbf{SYN\_SENT}: el cliente envió el primer paquete del \textit{handshake}
  TCP pero aún no recibió respuesta. Si persiste, puede indicar problemas de red.
\item \textbf{TIME\_WAIT}: la conexión terminó pero el kernel la mantiene
  brevemente para absorber paquetes retrasados.
\item \textbf{CLOSE\_WAIT}: el otro extremo cerró la conexión, esperando
  que este lado también cierre.
\end{itemize}

\subsubsection*{resolve\_hostname  DNS inverso}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} resolve\_hostname()}]
static void
resolve_hostname(const char *ip_str, char *out, size_t out_size)
{
  struct sockaddr_in sa;
  memset(&sa, 0, sizeof(sa));
  sa.sin_family = AF_INET;
  if (inet_pton(AF_INET, ip_str, &sa.sin_addr) != 1) {
    strncpy(out, ip_str, out_size - 1);
    return;
  }
  char host[128];
  int result = getnameinfo(
    (struct sockaddr *)&sa, sizeof(sa),
    host, sizeof(host),
    NULL, 0,
    NI_NOFQDN   //nombre corto sin dominio completo
  );
  if (result == 0 && strcmp(host, ip_str) != 0)
    strncpy(out, host, out_size - 1);
  else
    strncpy(out, ip_str, out_size - 1); //fallback a la IP numerica
  out[out_size - 1] = '\0';
}
\end{lstlisting}

Dado que las IPs en texto no son muy legibles, intentamos resolver cada IP remota a su nombre de dominio
mediante una consulta DNS inversa (PTR record). \texttt{getnameinfo()} hace la consulta; si el servidor tiene
un PTR record configurado, devuelve su hostname. Si no lo tiene (muchos servidores de CDN y nubes no lo
configuran), la función devuelve la IP original como fallback. El flag \texttt{NI\_NOFQDN} acorta el nombre
eliminando el dominio completo.

\subsubsection*{format\_bytes bytes a formato legible}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} format\_bytes()}]
static void
format_bytes(long bytes, char *out, size_t out_size)
{
  if (bytes >= 1024 * 1024)
    snprintf(out, out_size, "%.1f MB", bytes / (1024.0 * 1024.0));
  else if (bytes >= 1024)
    snprintf(out, out_size, "%.1f KB", bytes / 1024.0);
  else
    snprintf(out, out_size, "%ld B", bytes);
}
\end{lstlisting}

Convierte un número de bytes crudos a una cadena legible con unidades, los umbrales son $1024$ bytes para KB y
$1024 \times 1024$ para MB. Se usa solo para mostrar los datos de tráfico de \texttt{nf\_conntrack}.

% ----------------------------------------------------------------
\subsection*{collect\_net\_ifaces lectura de interfaces}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} collect\_net\_ifaces()}]
void
collect_net_ifaces(NetSnapshot *ns)
{
  FILE *f = fopen("/proc/net/dev", "r");
  if (!f) return;
  char line[256];
  ns->iface_count = 0;
  ns->total_rx_bytes = 0;
  ns->total_tx_bytes = 0;
  //Saltar las dos primeras lineas de encabezado
  fgets(line, sizeof(line), f);
  fgets(line, sizeof(line), f);
  while (fgets(line, sizeof(line), f) && ns->iface_count < MAX_IFACES) {
    IfaceStats *iface = &ns->ifaces[ns->iface_count];
    int matched = sscanf(line,
      " %31[^:]: %ld %ld %*ld %*ld %*ld %*ld %*ld %*ld %ld %ld",
      iface->name,
      &iface->rx_bytes, &iface->rx_packets,
      &iface->tx_bytes, &iface->tx_packets);
    if (matched != 5) continue;
    //Marcamos interfaces virtuales
    iface->is_virtual = (
      strcmp (iface->name, "lo")      == 0 ||
      strncmp(iface->name, "br-",  3) == 0 ||
      strncmp(iface->name, "veth", 4) == 0 ||
      strncmp(iface->name, "virbr",5) == 0 ||
      strcmp (iface->name, "docker0") == 0);
    //Acumulamos totales solo de interfaces fisicas reales
    if (!iface->is_virtual) {
      ns->total_rx_bytes += iface->rx_bytes;
      ns->total_tx_bytes += iface->tx_bytes;
    }
    ns->iface_count++;
  }
  fclose(f);
}
\end{lstlisting}

El archivo \texttt{/proc/net/dev} tiene dos líneas de encabezado que se saltan con dos llamadas a \texttt{fgets}. Cada línea de datos tiene el formato:

\begin{Verbatim}[fontsize=\small]
  eth0: rx_bytes rx_pkts rx_err rx_drop ... tx_bytes tx_pkts tx_err ...
\end{Verbatim}

El patrón de \texttt{sscanf} usa \texttt{\%*ld} para ignorar los campos que no necesitamos (errores, drops, fifo, frame), leyendo solo los bytes y paquetes. El patrón \texttt{\%31[\^{}:]} lee el nombre de la interfaz hasta
el carácter \texttt{:} que actúa como separador.

% ----------------------------------------------------------------
\subsection*{collect\_net\_conns conexiones y cruce con PIDs}
% ----------------------------------------------------------------

Esta es la función más compleja de la implementación, opera en dos fases.

\medskip

\textbf{Fase 1: leer conexiones desde /proc/net/tcp y /proc/net/udp:}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} collect\_net\_conns() fase 1}]
void
collect_net_conns(NetSnapshot *ns)
{
  ns->conn_count = 0;
    
  const char *files[] = { "/proc/net/tcp", "/proc/net/udp" };
  const char *protocols[] = { "TCP", "UDP" };
  
  for (int fi = 0; fi < 2 && ns->conn_count < MAX_CONNS; fi++) {
    FILE *f = fopen(files[fi], "r");
    if (!f)
      continue;
    
    char line[512];
    fgets(line, sizeof(line), f); //saltamos encabezado
    
    while (fgets(line, sizeof(line), f) && ns->conn_count < MAX_CONNS) {
      char local_hex[12], remote_hex[12];
      char local_port_hex[6], remote_port_hex[6];
      int state_num;
      long inode;
      int matched = sscanf(line,
			   " %*d: %8[^:]:%4s %8[^:]:%4s %X %*s %*s %*s %*d %*d %ld",
			   local_hex,  local_port_hex,
			   remote_hex, remote_port_hex,
			   &state_num, &inode);
      
      if (matched != 6)
	continue;
      
      NetConn *c = &ns->conns[ns->conn_count];
      strncpy(c->protocol, protocols[fi], sizeof(c->protocol) - 1);
      c->inode = inode;
      c->pid = -1;
      
      char ip[INET_ADDRSTRLEN];
      hex_to_ip(local_hex, ip, sizeof(ip));
      snprintf(c->local_addr,  sizeof(c->local_addr),
	       "%s:%d", ip, hex_to_port(local_port_hex));
      
      hex_to_ip(remote_hex, ip, sizeof(ip));
      snprintf(c->remote_addr, sizeof(c->remote_addr),
	       "%s:%d", ip, hex_to_port(remote_port_hex));
      
      strncpy(c->state, tcp_state_str(state_num), sizeof(c->state) - 1);
      
      if (state_num == 1 &&
	  strncmp(remote_hex, "00000000", 8) != 0) {
	char remote_ip[INET_ADDRSTRLEN];
	hex_to_ip(remote_hex, remote_ip, sizeof(remote_ip));
	resolve_hostname(remote_ip, c->remote_host, sizeof(c->remote_host));
      } else {
	strncpy(c->remote_host, c->remote_addr, sizeof(c->remote_host) - 1);
      }
      
      ns->conn_count++;
    }
    fclose(f);
  }
  /* Fase 2: cruzar inodos con PIDs */
}
\end{lstlisting}

Cada línea de \texttt{/proc/net/tcp} tiene el formato:

\begin{Verbatim}[fontsize=\small]
sl  local_address rem_address st tx_queue:rx_queue tr:tm uid timeout inode
0:  0101A8C0:1F90 0202A8C0:01BB 01 00000000:00000000 00:0 0 1000 1 12345
\end{Verbatim}

El patrón de \texttt{sscanf} extrae la IP y puerto local y remoto en hex, el estado como entero, y el inodo.
Los campos intermedios (colas, timer, uid) se ignoran con \texttt{\%*s} y \texttt{\%*d}.

\medskip

\textbf{Fase 2: cruzar inodos con PIDs:}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} collect\_net\_conns() fase 2}]
  /* Cruzamos inodos con PIDs
     cada proceso tiene sus file descriptors en /proc/[pid]/fd/
     los sockets aparecen como symlinks con destino "socket:[inode]"
     iteramos todos los PIDs y todos sus fd hasta encontrar coincidencia */
  DIR *proc_dir = opendir("/proc");
  if (!proc_dir)
    return;
  
  struct dirent *proc_entry;
  while ((proc_entry = readdir(proc_dir)) != NULL) {
    if (!isdigit(proc_entry->d_name[0]))
      continue;
    
    int pid = atoi(proc_entry->d_name);
    char fd_path[64];
    snprintf(fd_path, sizeof(fd_path), "/proc/%d/fd", pid);
    
    DIR *fd_dir = opendir(fd_path);
    if (!fd_dir)
      continue;

    struct dirent *fd_entry;
    while ((fd_entry = readdir(fd_dir)) != NULL) {
      if (fd_entry->d_name[0] == '.')
	continue;
      
      char link_path[128], link_target[128];
      snprintf(link_path, sizeof(link_path),
	       "/proc/%d/fd/%s", pid, fd_entry->d_name);

      ssize_t len = readlink(link_path, link_target, sizeof(link_target) - 1);
      if (len < 0)
	continue;
      link_target[len] = '\0';
      
      if (strncmp(link_target, "socket:[", 8) != 0)
	continue;
      
      long sock_inode;
      sscanf(link_target, "socket:[%ld]", &sock_inode);
      
      //Buscamos este inodo en nuestro arreglo de conexiones 
      for (int i = 0; i < ns->conn_count; i++) {
	if (ns->conns[i].inode == sock_inode && ns->conns[i].pid == -1) {
	  ns->conns[i].pid = pid;
	  //Leemos nombre del proceso
	  char comm_path[64];
	  snprintf(comm_path, sizeof(comm_path), "/proc/%d/comm", pid);
	  FILE *cf = fopen(comm_path, "r");
	  if (cf) {
	    fgets(ns->conns[i].proc_name, sizeof(ns->conns[i].proc_name), cf);
	    ns->conns[i].proc_name[strcspn(ns->conns[i].proc_name, "\n")] = '\0';
	    fclose(cf);
	  }
	}
      }
    }
    closedir(fd_dir);
  }
  closedir(proc_dir);
\end{lstlisting}

El mecanismo de cruce funciona porque en Linux todo socket es un archivo, y cada proceso tiene un directorio
\texttt{/proc/[pid]/fd/} donde sus file descriptors abiertos aparecen como enlaces simbólicos. Un socket
aparece con el destino \texttt{"socket:[12345]"} donde \texttt{12345} es su inodo. Al leer ese enlace con
\texttt{readlink()} y comparar el inodo con los que registramos en la fase 1, encontramos qué proceso es dueño
de cada conexión.

\medskip

\textbf{Desafío encontrado:} sin root, \texttt{opendir("/proc/[pid]/fd")} falla para procesos de otros usuarios,
devolviendo \texttt{NULL}. El código lo maneja con \texttt{if (!fd\_dir) continue}, simplemente salta ese
proceso y continúa. Con root, se puede abrir el directorio de todos los procesos y el cruce es completo.

\subsection*{collect\_conntrack tráfico por conexión (solo root)}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} collect\_conntrack()}]
void
collect_conntrack(NetSnapshot *ns)
{
  FILE *f = fopen("/proc/net/nf_conntrack", "r");
  if (!f) {
    fprintf(stderr, "  [!] nf_conntrack no disponible\n");
    return;
  }
  
  char line[1024];
  
  while (fgets(line, sizeof(line), f)) {
    if (strncmp(line, "ipv4", 4) != 0)
      continue;
    
    char src_orig[48] = {0};
    char dst_orig[48] = {0};
    int sport_orig = 0;
    int dport_orig = 0;
    
    char *p;
    p = strstr(line, "src=");
    if (!p)
      continue;
    sscanf(p + 4, "%47s", src_orig);
    
    //extraemos IP destino con el mismo patron
    p = strstr(line, "dst=");
    if (!p)
      continue;
    sscanf(p + 4, "%47s", dst_orig);
    
    //extraer puerto origen: +6 salta "sport="
    p = strstr(line, "sport=");
    if (!p)
      continue;
    sscanf(p + 6, "%d", &sport_orig);
    
    //extraer puerto destino: +6 salta "dport="
    p = strstr(line, "dport=");
    if (!p)
      continue;
    sscanf(p + 6, "%d", &dport_orig);
    
    long bytes_orig = 0, bytes_reply = 0;
    long pkts_orig = 0, pkts_reply = 0;
    int has_acct = 0;
    
    char *cursor = line;
    int occ = 0;
    while ((cursor = strstr(cursor, "bytes=")) != NULL) {
      long val;
      sscanf(cursor + 6, "%ld", &val); //+6 salta "bytes="
      if (occ == 0) {
	bytes_orig = val;
	has_acct = 1;
      } else {
	bytes_reply = val;
      }
      occ++;
      cursor++;
    }
    
    cursor = line; occ = 0;
    while ((cursor = strstr(cursor, "packets=")) != NULL) {
      long val;
      sscanf(cursor + 8, "%ld", &val); //+8 salta "packets="
      if (occ == 0)
	pkts_orig  = val;
      else
	pkts_reply = val;
      occ++;
      cursor++;
    }
    
    char local_str[48], remote_str[48];
    snprintf(local_str,  sizeof(local_str), "%s:%d", src_orig, sport_orig);
    snprintf(remote_str, sizeof(remote_str), "%s:%d", dst_orig, dport_orig);
    
    for (int i = 0; i < ns->conn_count; i++) {
      NetConn *c = &ns->conns[i];
      if (strcmp(c->local_addr,  local_str)  == 0 &&
	  strcmp(c->remote_addr, remote_str) == 0) {
	c->bytes_sent = bytes_orig;
	c->bytes_recv = bytes_reply;
	c->packets_sent = pkts_orig;
	    c->packets_recv = pkts_reply;
	    c->has_traffic_data = has_acct; /* 0 si no hay acct   */
	    break; /* cada conexion es unica, no seguir buscando  */
      }
    }
  }
  
  fclose(f);
}
\end{lstlisting}

El archivo \texttt{/proc/net/nf\_conntrack} tiene un formato por línea como:

\begin{Verbatim}[fontsize=\small]
ipv4 2 tcp 6 86399 ESTABLISHED src=192.168.1.1 dst=1.2.3.4 sport=12345
     dport=443 packets=100 bytes=15000 src=1.2.3.4 dst=192.168.1.1
     sport=443 dport=12345 packets=200 bytes=120000 [ASSURED]
\end{Verbatim}

Los campos \texttt{src}, \texttt{dst}, \texttt{sport} y \texttt{dport} aparecen dos veces: la primera vez para
la dirección original (lo que enviamos) y la segunda para el reply (lo que recibimos). La función usa
\texttt{strstr} en lugar de \texttt{sscanf} posicional porque el orden de los campos puede variar entre
versiones del kernel.

\medskip

\textbf{Desafío importante:} los campos \texttt{bytes=} y \texttt{packets=} solo aparecen en la línea si el
módulo \texttt{nf\_conntrack} fue cargado con la contabilidad habilitada (\texttt{nf\_conntrack\_acct=1}), si
no está habilitada, la línea no tiene esos campos y \texttt{has\_acct} queda en 0, lo que significa que no se
muestran datos de tráfico por conexión, lo cual es preferible a mostrar ceros engañosos. Además, los contadores
solo empiezan desde el momento en que se habilita la contabilidad, no retroactivamente para conexiones ya
establecidas.

\medskip

Para habilitarlo:

\begin{Verbatim}[frame=single, rulecolor=\color{black!20}, fontsize=\small]
sudo sysctl net.netfilter.nf_conntrack_acct=1
\end{Verbatim}

\subsection*{cmp\_rx comparador para ordenamiento}

\begin{lstlisting}[style=modernc, caption={\texttt{net\_monitor.c} cmp\_rx()}]
static int
cmp_rx(const void *a, const void *b)
{
  const IfaceStats *ia = (const IfaceStats *)a;
  const IfaceStats *ib = (const IfaceStats *)b;
  return (ib->rx_bytes > ia->rx_bytes) - (ib->rx_bytes < ia->rx_bytes);
}
\end{lstlisting}

Ordena las interfaces de mayor a menor por bytes recibidos, usando el mismo patrón de comparación sin resta
directa que \texttt{cmp\_mem} en la primera implementación, para evitar overflow en valores grandes de tipo
\texttt{long}.

% ----------------------------------------------------------------
\subsection*{Limitación: datos de velocidad en tiempo real}
% ----------------------------------------------------------------

Los valores de RX/TX bytes en \texttt{/proc/net/dev} son contadores acumulados desde el arranque del sistema,
no velocidad actual, para calcular cuántos KB/s se están transfiriendo en este momento se necesitan dos lecturas
separadas por un intervalo de tiempo y calcular la diferencia. Esto no es posible en un escaneo único y se
implementará en la siguiente fase, donde el hilo recolector guardará el snapshot anterior y calculará el delta
en cada tick.

\medskip

De igual forma, incluso con root y \texttt{nf\_conntrack\_acct} habilitado, si ninguna aplicación está enviando
o recibiendo paquetes en el momento del escaneo, los contadores de esa conexión mostrarán solo el total
histórico desde que se estableció la conexión, no actividad reciente. No hay forma de distinguir una conexión
\textit{idle} de una activa sin hacer la comparación entre dos snapshots.

\section*{Tercera Implementación: Interfaz de terminal con ncurses}
% ================================================================

\subsection*{Descripción general}

Esta implementación sustituye el \texttt{printf} de las dos anteriores por una interfaz de terminal interactiva
construida con la biblioteca \textbf{ncurses}. El resultado visible es el que muestran las capturas del proyecto
: una pantalla dividida en header, contenido scrolleable y footer, con colores y actualización en tiempo real,
todo dentro de la misma terminal sin abrir ninguna ventana gráfica.

\medskip

Se añaden dos archivos: \texttt{include/ui.h} con las definiciones de estado, y
\texttt{src/ui.c} con toda la lógica de presentación. El \texttt{main.c} se
reduce a una sola llamada: \texttt{ui\_run()}.

\medskip

El mayor desafío de esta implementación fue el desconocimiento previo de ncurse, a diferencia de \texttt{printf}
, que imprime líneas de forma secuencial, \texttt{ncurses} trabaja con un modelo de \textbf{pantalla virtual}
en la que uno debe posicionar cada carácter en coordenadas \texttt{(fila, columna)}, aplicas colores y atributos
, y al final llamas a una función que vuelca solo los cambios a la pantalla real. Esto permite que el header y
el footer sean visualmente estáticos mientras solo el contenido central se redibuja, y elimina el parpadeo que
tendría un \texttt{clear} + \texttt{printf} repetido.

% ----------------------------------------------------------------
\subsection*{Cómo funciona \texttt{ncurses}}
% ----------------------------------------------------------------

\texttt{ncurses} intercepta la terminal al llamar \texttt{initscr()} y la divide en ventanas (\texttt{WINDOW*}).
Cada ventana tiene su propio buffer en memoria. Las funciones de dibujo (\texttt{mvwprintw}, \texttt{waddch},
etc.) escriben en ese buffer, no en pantalla. Solo cuando se llama \texttt{doupdate()} ncurses compara cada
buffer con lo que la pantalla muestra actualmente y escribe únicamente los caracteres que cambiaron.
Por eso no hay parpadeo aunque se redibuje todo cada tick.

\medskip

El ciclo de vida del programa con ncurses sigue siempre el mismo patrón:

\begin{center}
\begin{tikzpicture}[node distance=0.65cm]
    \node (init)    [startstop]                         {initscr()};
    \node (loop)    [process,  below=of init]           {getch() sin bloqueo\\leer input del usuario};
    \node (erase)   [process,  below=of loop]           {werase() cada ventana\\borrar buffer en memoria};
    \node (draw)    [process,  below=of erase]          {mvwprintw / waddch\\dibujar en buffers};
    \node (refresh) [process,  below=of draw]           {wnoutrefresh() + doupdate()\\volcar a pantalla};
    \node (sleep)   [process,  below=of refresh]        {usleep(100ms)\\esperar siguiente frame};
    \node (end)     [startstop,below=of sleep]          {endwin()};

    \draw [arrow] (init)    -- (loop);
    \draw [arrow] (loop)    -- (erase);
    \draw [arrow] (erase)   -- (draw);
    \draw [arrow] (draw)    -- (refresh);
    \draw [arrow] (refresh) -- (sleep);
    \draw [arrow] (sleep.east) -- ++(1.8,0) |- (loop.east)
        node[midway, right, font=\small] {running};
    \draw [arrow] (sleep)   -- (end) node[midway,right,font=\small]{q};
\end{tikzpicture}
\end{center}

\subsection*{cmp\_mem\_ui comparador para qsort}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{ui.c} cmp\_mem\_ui()}]
static int
cmp_mem_ui(const void *a,
	   const void *b)
{
  const ProcessInfo *pa = (const ProcessInfo *)a;
  const ProcessInfo *pb = (const ProcessInfo *)b;
  return (pb->memory_kb > pa->memory_kb) - (pb->memory_kb < pa->memory_kb);
}
\end{lstlisting}

Esta función existe en \texttt{ui.c} y no en \texttt{monitor.c} por una razón de alcance, en la implementación
anterior el ordenamiento se hacía dentro de \texttt{print\_snapshot}, que ya no se usa en la interfaz ncurses.
\texttt{draw\_content\_memory} necesita ordenar la copia local de procesos antes de dibujarla, así que se define
el comparador aquí.

\medskip

La función está marcada \texttt{static} para que no sea visible fuera del módulo, está en el scope del módulo y
no anidada dentro de \texttt{draw\_content\_memory} porque las
\textbf{funciones anidadas no forman parte del estándar C99}, son una extensión de GCC que puede causar
incompatibilidades. Al tenerla en el scope del módulo el código compila con cualquier compilador C99 o posterior.

}
\end{lstlisting}

\textbf{\texttt{newwin(filas, cols, fila\_inicio, col\_inicio)}} crea una subventana de ncurses con su propio
buffer de caracteres y su propio sistema de coordenadas. A partir de la llamada,
\texttt{mvwprintw(win, 0, 0, ...)} siempre significa ``fila 0 de esa ventana'', independientemente de dónde
esté la ventana en la pantalla real. Esto permite que las funciones de dibujo de header, content y footer sean
completamente independientes entre sí, ninguna necesita saber la posición absoluta de las otras.

\medskip

\textbf{\texttt{delwin(win)}} libera la memoria del buffer de la ventana, es obligatorio llamarlo antes de crear
una nueva ventana con las mismas dimensiones, sin \texttt{delwin}, cada redimensionado acumularía ventanas
huérfanas en memoria. Por eso la función primero destruye las ventanas existentes y luego crea las nuevas con
el tamaño actual de la terminal, que se obtiene con \texttt{getmaxyx(stdscr, rows, cols)}.

\medskip

Esta función se llama al inicio y también cuando ncurses entrega \texttt{KEY\_RESIZE}, la señal interna que
indica que el usuario redimensionó la ventana del terminal.

% ----------------------------------------------------------------
\subsection*{draw\_bar wattron, waddch, wattroff}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{ui.c} draw\_bar()}]
static void
draw_bar(WINDOW *win,
	 int pct,
	 int width)
{
  int filled = (int)((double)pct / 100.0 * width);
  waddch(win, '[');
  for (int i = 0; i < width; i++) {
    if (i < filled) {
      int col = pct > 85 ? COL_HIGH : pct > 60 ? COL_MED : COL_LOW;
      wattron(win, COLOR_PAIR(col));
      waddch(win, ACS_BLOCK);
      wattroff(win, COLOR_PAIR(col));
      wattron(win, COLOR_PAIR(COL_HEADER));
    } else {
      waddch(win, '.');
    }
  }
  waddch(win, ']');
}
\end{lstlisting}

\textbf{\texttt{waddch(win, ch)}} añade un solo carácter al buffer de la ventana en la posición actual del
cursor interno de esa ventana, avanzando el cursor una posición. Es el equivalente ncurses de \texttt{putchar},
pero escribe en el buffer de una ventana específica.

\medskip

\textbf{\texttt{wattron(win, attr)}} activa un atributo de texto en la ventana \texttt{win}. Todo lo que se
imprima después tendrá ese atributo hasta que se llame \texttt{wattroff}, los atributos más usados son
\texttt{COLOR\_PAIR(n)} para color, \texttt{A\_BOLD} para negrita y \texttt{A\_REVERSE} para invertir
fondo y textom, se pueden combinar con el operador \texttt{|}.

\medskip

\textbf{\texttt{wattroff(win, attr)}} desactiva el atributo, el patrón correcto siempre es: activar antes de
imprimir, desactivar inmediatamente después. Dejar un color activo más tiempo del necesario puede colorear texto
que no debería estarlo si en el futuro se añade código entre medio.

\medskip

\textbf{\texttt{ACS\_BLOCK}} es una constante de ncurses que representa el carácter de bloque sólido, el
prefijo \texttt{ACS\_} (Alternative Character Set) indica que ncurses usará el carácter correcto para la
terminal actual, en terminales modernas es el bloque Unicode, en terminales antiguas usa el carácter más
parecido disponible.

% ----------------------------------------------------------------
\subsection*{draw\_header wbkgd, werase, strftime, wnoutrefresh}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{ui.c} draw\_header()}]
static void
draw_header(DisplayMode mode)
{
  int cols = getmaxx(win_header);
  wbkgd(win_header, COLOR_PAIR(COL_HEADER));
  werase(win_header);
  const char *title = (mode == MODE_MEMORY)
    ? "System Monitor [Memory]"
    : "System Monitor [Net]";
  wattron(win_header, COLOR_PAIR(COL_HEADER) | A_BOLD);
  mvwprintw(win_header, 0, 1, "%s", title);
  if (getuid() == 0)
    mvwprintw(win_header, 0, (int)strlen(title) + 3, "[root]");
  time_t now = time(NULL);
  char timebuf[32];
  strftime(timebuf, sizeof(timebuf), "%a %d %b  %H:%M:%S", localtime(&now));
  mvwprintw(win_header, 0, cols - (int)strlen(timebuf) - 1, "%s", timebuf);
  wattroff(win_header, COLOR_PAIR(COL_HEADER) | A_BOLD);
  wnoutrefresh(win_header);
}
\end{lstlisting}

\textbf{\texttt{wbkgd(win, attr)}} establece el carácter y atributo de fondo de toda la ventana, sin esta
llamada, las celdas vacías de la ventana usarían el atributo por defecto del terminal, el header mostraría un
parche de color cyan solo donde hay texto, dejando el resto en negro, con \texttt{wbkgd} todo el
ancho del header queda en cyan aunque no haya texto.

\medskip

\textbf{\texttt{werase(win)}} borra el contenido del buffer de la ventana llenándolo con el carácter de fondo
establecido por \texttt{wbkgd}, es el equivalente de \texttt{clear()} pero para una ventana específica.
La diferencia con \texttt{wclear} es que \texttt{werase} no fuerza un redibujado completo en
el siguiente \texttt{refresh}.

\medskip

\textbf{\texttt{mvwprintw(win, fila, col, fmt, ...)}} combina un movimiento de cursor y un \texttt{printf} en
una sola llamada, el prefijo \texttt{mv} mueve el cursor a \texttt{(fila, col)} dentro de la ventana antes de
imprimir, es la función de impresión posicional más usada en ncurses.

\medskip

\textbf{\texttt{strftime(buf, size, fmt, tm)}} formatea una estructura \texttt{struct tm} a texto según el
patrón \texttt{fmt}, el patrón \texttt{"\%a \%d \%b  \%H:\%M:\%S"} produce cadenas como
\texttt{"Tue 27 May  00:01:10"}: día de la semana abreviado, día del mes, mes abreviado, y hora en formato 24h.

\medskip

\textbf{\texttt{wnoutrefresh(win)}} marca la ventana como ``pendiente de actualizar'' pero
\textbf{no escribe nada en la pantalla real todavía}, el volcado real ocurre cuando se llama
\texttt{doupdate()} al final del frame. La razón de separar estas dos operaciones es evitar parpadeo, si cada
ventana hiciera su propio \texttt{wrefresh}, la pantalla se actualizaría tres veces por frame
(header, content, footer) y el ojo humano percibiría un parpadeo entre estados parciales.
Con \texttt{wnoutrefresh} + \texttt{doupdate}, las tres ventanas se vuelcan a pantalla en un solo paso.

\subsection*{draw\_content\_memory scroll y color por filas}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{ui.c} draw\_content\_memory()}]
static void
draw_content_memory(const SystemSnapshot *snap,
		    UIState *state)
{
  int rows, cols;
  getmaxyx(win_content, rows, cols);
  (void)cols;
  werase(win_content);
  wattron(win_content, COLOR_PAIR(COL_TITLE) | A_BOLD);
  mvwprintw(win_content, 0, 0,
	    "%-6s  %-6s  %-16s  %-10s  %-10s  %-8s  %-15s  %s",
	    "PID", "PPID", "Nombre", "RSS KB",
	    "VmSize KB", "Estado", "Padre", "Comando");
  wattroff(win_content, COLOR_PAIR(COL_TITLE) | A_BOLD);
  mvwhline(win_content, 1, 0, ACS_HLINE, cols);
  ProcessInfo sorted[MAX_PROCS];
  memcpy(sorted, snap->processes,
	 snap->process_count * sizeof(ProcessInfo));
  qsort(sorted, snap->process_count, sizeof(ProcessInfo), cmp_mem_ui);
  int available = rows - 2;
  int total = snap->process_count;
  if (state->scroll_offset > total - available)
    state->scroll_offset = total - available;
  if (state->scroll_offset < 0)
    state->scroll_offset = 0;
  for (int i = 0; i < available && (state->scroll_offset + i) < total; i++) {
    int screen_row = 2 + i;
    const ProcessInfo *p = &sorted[state->scroll_offset + i];
    int col = (p->memory_kb > 500000) ? COL_HIGH :
      (p->memory_kb > 100000) ? COL_MED : COL_NORMAL;
    const char *st = p->state == 'R' ? "running"  :
      p->state == 'S' ? "sleeping" :
      p->state == 'D' ? "waiting"  :
      p->state == 'Z' ? "zombie"   : "other";
    char cmd[36];
    snprintf(cmd, sizeof(cmd), "%.35s", p->cmdline[0] ? p->cmdline : p->name);
    wattron(win_content, COLOR_PAIR(col));
    mvwprintw(win_content, screen_row, 0,
	      "%-6d  %-6d  %-16s  %-10ld  %-10ld  %-8s  %-15s  %s",
	      p->process_id, p->parent_process_id,
	      p->name, p->memory_kb, p->vm_size_kb,
	      st, p->parent_name, cmd);
    wattroff(win_content, COLOR_PAIR(col));
  }
  if (total > available) {
    int pct = (state->scroll_offset * 100) / (total - available > 0 ? total - available : 1);
    mvwprintw(win_content, rows / 2, cols - 5, " %3d%%", pct);
  }
  wnoutrefresh(win_content);
}
\end{lstlisting}

El scroll se implementa con un índice \texttt{scroll\_offset} que indica cuál es el primer elemento del arreglo
ordenado a mostrar, en cada frame se dibujan exactamente \texttt{available = rows - 2} filas, empezando desde
\texttt{sorted[scroll\_offset]}. Las teclas \texttt{↑} y \texttt{↓} en el loop principal simplemente
decrementan o incrementan \texttt{scroll\_offset}, y el siguiente frame refleja el cambio automáticamente.

\medskip

Las guardas \texttt{if (state->scroll\_offset > total - available)} evitan que el scroll se pase del final de
la lista, y \texttt{if (...< 0)} evita valores negativos si se presiona \texttt{↑} en la primera posición.

\medskip

La función \textbf{\texttt{mvwhline(win, fila, col, ch, n)}} dibuja \texttt{n} repeticiones del carácter
\texttt{ch} en horizontal, con \texttt{ACS\_HLINE} produce la línea separadora entre encabezados y datos.

\begin{lstlisting}[style=modernc, caption={\texttt{ui.c} draw\_content\_net()}]
static void
draw_content_net(const NetSnapshot *ns,
		 UIState *state)
{
  int rows, cols;
  getmaxyx(win_content, rows, cols);
  (void)cols;
  werase(win_content);
  wattron(win_content, COLOR_PAIR(COL_TITLE) | A_BOLD);
  mvwprintw(win_content, 0, 0, "Interfaces fisicas:");
  wattroff(win_content, COLOR_PAIR(COL_TITLE) | A_BOLD);
  mvwprintw(win_content, 1, 0,
	    "%-12s  %15s  %15s  %12s  %12s",
	    "Interfaz", "RX bytes", "TX bytes",
	    "RX pkts", "TX pkts");
  mvwhline(win_content, 2, 0, ACS_HLINE, cols);
  int iface_row = 3;
  for (int i = 0; i < ns->iface_count; i++) {
    const IfaceStats *iface = &ns->ifaces[i];
    if (iface->is_virtual)
      continue;
    wattron(win_content, COLOR_PAIR(COL_LOW));
    mvwprintw(win_content, iface_row++, 0,
	      "%-12s  %15ld  %15ld  %12ld  %12ld",
	      iface->name,
	      iface->rx_bytes, iface->tx_bytes,
	      iface->rx_packets, iface->tx_packets);
    wattroff(win_content, COLOR_PAIR(COL_LOW));
  }
  int conn_start = iface_row + 1;
  mvwhline(win_content, conn_start - 1, 0, ACS_HLINE, cols);
  wattron(win_content, COLOR_PAIR(COL_TITLE) | A_BOLD);
  mvwprintw(win_content, conn_start, 0, "Conexiones activas:");
  wattroff(win_content, COLOR_PAIR(COL_TITLE) | A_BOLD);
  mvwprintw(win_content, conn_start + 1, 0,
	    "%-5s  %-5s  %-22s  %-28s  %-13s  %s",
	    "PID", "Proto", "Local", "Remoto/Host",
	    "Estado", "Proceso");
  mvwhline(win_content, conn_start + 2, 0, ACS_HLINE, cols);
  int header_rows = conn_start + 3; //filas usadas por interfaces + enc
  int available = rows - header_rows;
  int visible[MAX_CONNS];
  int visible_count = 0;
  for (int i = 0; i < ns->conn_count; i++) {
    const NetConn *c = &ns->conns[i];
    if (c->pid == -1)
      continue;
    if (strcmp(c->protocol, "UDP") == 0 && strncmp(c->remote_addr, "0.0.0.0", 7) == 0)
      continue;
    visible[visible_count++] = i;
  }
  if (state->scroll_offset > visible_count - available)
    state->scroll_offset = visible_count - available;
  if (state->scroll_offset < 0)
    state->scroll_offset = 0;
  for (int i = 0; i < available && (state->scroll_offset + i) < visible_count; i++) {
    int ci = visible[state->scroll_offset + i];
    const NetConn *c = &ns->conns[ci];
    int screen_row = header_rows + i;
    int col = (strcmp(c->state, "ESTABLISHED") == 0) ? COL_LOW :
      (strcmp(c->state, "SYN_SENT") == 0) ? COL_MED : COL_NORMAL;
    const char *remote = (c->remote_host[0] &&
			  strcmp(c->remote_host, c->remote_addr) != 0)
      ? c->remote_host : c->remote_addr;
    wattron(win_content, COLOR_PAIR(col));
    mvwprintw(win_content, screen_row, 0,
	      "%-5d  %-5s  %-22s  %-28s  %-13s  %-16s",
	      c->pid, c->protocol,
	      c->local_addr, remote,
	      c->state, c->proc_name);
    if (c->has_traffic_data) {
      char sent[16], recv[16];
      if(c->bytes_sent >= 1024*1024)
	snprintf(sent, sizeof(sent), "%.1fMB", c->bytes_sent / (1024.0*1024.0));
      else if (c->bytes_sent >= 1024)
	snprintf(sent, sizeof(sent), "%.1fKB", c->bytes_sent / 1024.0);
      else
	snprintf(sent, sizeof(sent), "%ldB", c->bytes_sent);
      if (c->bytes_recv >= 1024*1024)
	snprintf(recv, sizeof(recv), "%.1fMB", c->bytes_recv / (1024.0*1024.0));
      else if (c->bytes_recv >= 1024)
	snprintf(recv, sizeof(recv), "%.1fKB", c->bytes_recv / 1024.0);
      else
	snprintf(recv, sizeof(recv), "%ldB", c->bytes_recv);
      wprintw(win_content, "  ^%-8s v%-8s p^%ld/v%ld",
	      sent, recv, c->packets_sent, c->packets_recv);
    }
    wattroff(win_content, COLOR_PAIR(col));
  }
  wnoutrefresh(win_content);
}
\end{lstlisting}

La sección de interfaces es fija: siempre ocupa las primeras filas del content y no participa en el scroll, la
sección de conexiones sí scrollea, usando el mismo mecanismo de \texttt{scroll\_offset} que el modo memoria.
El arreglo \texttt{visible[]} filtra previamente las conexiones que no deben mostrarse
(sin PID resuelto, sockets UDP sin destino), para que \texttt{scroll\_offset} opere sobre el conjunto de filas
realmente visibles y no sobre el arreglo completo que incluye entradas descartadas.

% ----------------------------------------------------------------
\subsection*{ui\_run el loop principal}
% ----------------------------------------------------------------

\begin{lstlisting}[style=modernc, caption={\texttt{ui.c} ui\_run() inicialización}]
void
ui_run()
{
  setlocale(LC_ALL, "");
  initscr();
  cbreak();
  noecho();
  keypad(stdscr, TRUE);
  nodelay(stdscr, TRUE);
  curs_set(0);
  if (!has_colors()) {
    endwin();
    fprintf(stderr, "El terminal no soporta colores\n");
    return;
  }
  init_colors();
  create_windows();
  UIState state = { MODE_MEMORY, 0, 1 };
  SystemSnapshot mem_snap;
  NetSnapshot net_snap;
  memset(&mem_snap, 0, sizeof(mem_snap));
  memset(&net_snap, 0, sizeof(net_snap));
  collect_memory(&mem_snap);
  collect_processes(&mem_snap);
  collect_net_ifaces(&net_snap);
  collect_net_conns(&net_snap);
  if (is_root())
    collect_conntrack(&net_snap);
  int tick_counter = 0;
  const int TICK = 10;
  while (state.running) {
    int ch = getch();
    switch (ch) {
    case 'q':
    case 'Q':
      state.running = 0;
      break;

    case 'n':
    case 'N':
      /* codigo mas adelante */
      break;

    case KEY_UP:
      if (state.scroll_offset > 0)
	state.scroll_offset--;
      break;
    case KEY_DOWN:
      state.scroll_offset++;
      break;
    case KEY_RESIZE:
      //el usuario redimensiono la terminal, reconstruir ventanas
      create_windows();
      break;
    default:
      break;
    }
\end{lstlisting}

\texttt{setlocale(LC\_ALL, "")} es obligatorio antes de \texttt{initscr} para que ncurses pueda mostrar
caracteres multibyte como \texttt{ACS\_BLOCK} y \texttt{ACS\_HLINE}, sin esta llamada esos caracteres aparecen
como símbolos incorrectos en terminales UTF-8.

\medskip

\texttt{nodelay(stdscr, TRUE)} es clave para el funcionamiento fluido del monitor, hace que \texttt{getch()}
devuelva \texttt{ERR} inmediatamente si no hay input del usuario, en lugar de bloquear el hilo esperando una
tecla. Sin esto, el programa se congela en \texttt{getch()} y nunca llega a redibujar la pantalla.

\begin{lstlisting}[style=modernc, caption={\texttt{ui.c} ui\_run() manejo de N con sudo}]
    case 'n':
    case 'N':
      if (state.mode == MODE_MEMORY) {
        if (getuid() != 0) {
	  if (in_docker()) {
	    /* en Docker sin --privileged no hay forma de escalar,
	       mostrar mensaje claro al usuario */
	  }
	  def_prog_mode();
	  endwin();
	  printf("\n[sysmon] El modo red requiere root.\n");
	  printf("[sysmon] Se solicitaran credenciales de sudo.\n\n");
	  fflush(stdout);
	  int ok = system("sudo -v 2>/dev/null");
	  reset_prog_mode();
	  refresh();
	  create_windows();
	  if (ok != 0)
	    break;
	  endwin();
	  printf("\n[sysmon] Autenticado. Relanzando con privilegios...\n");
	  fflush(stdout);
	  char self[256];
	  ssize_t len = readlink("/proc/self/exe", self, sizeof(self) - 1);
	  if (len > 0) {
	    self[len] = '\0';
	    char *args[] = { "sudo", self, NULL };
	    execvp("sudo", args);
	  }
	  exit(EXIT_FAILURE);
        }
        state.mode = MODE_NET;
        state.scroll_offset = 0;
      } else {
        state.mode = MODE_MEMORY;
        state.scroll_offset = 0;
      }
      break;
\end{lstlisting}

El manejo de la tecla \texttt{N} resuelve un problema interesante, el modo red necesita root para leer
\texttt{nf\_conntrack}, pero el programa puede haber arrancado sin privilegios. La solución es salir
temporalmente de ncurses con \texttt{def\_prog\_mode()} + \texttt{endwin()} para poder imprimir en la terminal
normal, pedir credenciales con \texttt{sudo -v}, y si la autenticación tiene éxito, relanzar el propio
ejecutable con \texttt{execvp("sudo", args)}.

\medskip

\texttt{readlink("/proc/self/exe", ...)} obtiene la ruta absoluta del ejecutable actual, más fiable que
\texttt{argv[0]}, que puede ser una ruta relativa o simplemente el nombre. Después \texttt{execvp} reemplaza el
proceso actual por \texttt{sudo \textit{ruta}}, que arranca el monitor de nuevo con UID 0.

\medskip

\texttt{def\_prog\_mode()} y \texttt{reset\_prog\_mode()} son un par de funciones de ncurses que guardan y
restauran la configuración del terminal, se usan cuando necesitamos salir brevemente de ncurses
(para imprimir en terminal normal o pedir input) y volver sin tener que reinicializar todo el entorno.

\begin{lstlisting}[style=modernc, caption={\texttt{ui.c} ui\_run() tick y cierre}]
    draw_header(state.mode);
    if (state.mode == MODE_MEMORY) {
      draw_content_memory(&mem_snap, &state);
      draw_footer_memory(&mem_snap);
    } else {
      draw_content_net(&net_snap, &state);
      draw_footer_net(&net_snap);
    }
    doupdate();
    tick_counter++;
    if (tick_counter >= TICK) {
      tick_counter = 0;
      if (state.mode == MODE_MEMORY) {
	memset(&mem_snap, 0, sizeof(mem_snap));
	collect_memory(&mem_snap);
	collect_processes(&mem_snap);
      } else {
	memset(&net_snap, 0, sizeof(net_snap));
	collect_net_ifaces(&net_snap);
	collect_net_conns(&net_snap);
	if (is_root())
	  collect_conntrack(&net_snap);
      }
    }
    usleep(100 * 1000);
  }
  delwin(win_header);
  delwin(win_content);
  delwin(win_footer);
  endwin();
}
\end{lstlisting}

El tick de recolección está desacoplado del frame rate: la pantalla se actualiza a 10 fps (cada 100 ms) pero los
datos se recolectan solo una vez por segundo (cada 10 frames), esto evita que la lectura de \texttt{/proc}, que
implica muchas llamadas al sistema, compita con el dibujado de la UI en cada frame.

\medskip

Al terminar el loop, \texttt{delwin} libera las tres ventanas y \texttt{endwin()} restaura la terminal a su
estado original, configuración del cursor, modo de input, colores. Esta llamada es \textbf{siempre obligatoria}
antes de salir, sin ella la terminal queda en modo ncurses y el usuario no puede ver lo que escribe hasta cerrar
y reabrir la sesión.

\begin{Verbatim}[frame=single, rulecolor=\color{black!20}, fontsize=\small]
# instalar ncurses si no está (Fedora)
sudo dnf install ncurses-devel

# instalar ncurses si no está (Debian/Ubuntu)
sudo apt install libncurses-dev

# compilar
cmake -B build && cmake --build build

# lanzar (modo memoria por defecto)
./build/src/sysmon

# dentro del monitor:
#   N  -> cambiar a modo red (pide sudo la primera vez)
#   ↑↓ -> scroll por la tabla
#   q  -> salir
\end{Verbatim}
